# 비교 조건과 입출력 점검

점검일: 2026-11-05. 대상은 FoundGrasp(+refiner), AnyGrasp, RNGNet, GFLA입니다.
`configs/benchmark.yaml`에서 검출기 이름만 바꿔 **방법별 추론 파이프라인을 같은
실장비 실행 조건에서 비교**합니다. 모델 내부 처리나 입력 정보량까지 동일한 실험은 아닙니다.

## 공통 조건

- RGB는 RGB 순서의 uint8, depth는 미터, 무효 depth는 0입니다.
- 동일한 캘리브레이션 K/D로 RGB와 depth를 함께 보정합니다. 저장 프레임 재생은
  이미 보정된 영상에 보정을 다시 적용하지 않습니다.
- depth만 같은 ROI 밖을 0으로 마스킹합니다. RGB를 사용하는 방법에는 전체 RGB가 전달됩니다.
- 출력은 카메라 광학 좌표의 GraspNet `N×17`: score, width/height/depth(m),
  회전행렬, translation(m), object ID. 회전행렬 첫 열은 접근 방향, 둘째 열은 개방 방향입니다.
- 모델 내부 처리 후 score > 0, 폭 ≤ 100mm, 공유 충돌 검사, ROI를 적용합니다.
  공유 검사는 **마스킹 전 전체 depth**와 같은 voxel 10mm / approach 50mm / threshold 0.01을 씁니다.
- 같은 작업 공간·기울기·IK·180° 대칭·전체 경로 선정과 로봇·그리퍼 모션 설정을 씁니다.
- 시각화는 필터 후 후보 중 점수 순 최대 50개이며 겹치는 후보도 표시합니다.
  표시 개수는 실제 선정에 사용할 후보 수를 제한하지 않습니다.

## 방법 고유 처리 — 비교 시 함께 명시

| 방법 | 입력 처리 | 고유 후보 처리 | 실행 개방 폭 |
|---|---|---|---|
| FoundGrasp | RGB + metric XYZ. RGB만 고정 평균/표준편차 정규화 | refiner·측정면 검사, grasp NMS, 최종 top-50 | 최종 출력 그대로. 내부 decode ×1.2와 refiner 폭 재선택 유지 |
| AnyGrasp | 유효 depth만 카메라 XYZ 점군으로 변환; RGB 미사용 | 비공개 SDK 내부 충돌 검사 + NMS | SDK 출력 ×1.2, 최대 100mm |
| RNGNet | RGB-D, ROI의 0을 제외한 유효 depth 평균 정규화 | 최대 48개 영역 × 영역당 10개, 원본 내부 충돌 검사; 최종 3D NMS 없음 | 예측 폭 ×1.2, 최대 100mm |
| GFLA | RGB-D + 촬영 당시 `T_base_cam`; 작업대 좌표계=로봇 베이스 가정 | 원본 SDF·force closure·3cm/30° NMS | 원본 +16mm를 포함한 출력 ×1.2, 최대 100mm |

GFLA만 촬영 자세/작업대 정보가 인식 입력에 들어갑니다. 이 차이는 manifest와 프레임에
기록합니다. 동일 정보량의 비교라고 해석하지 않습니다. 모델별 score도 서로 같은
성공 확률이 아니므로 절대값이나 후보 개수만으로 모델 성능을 비교하지 않습니다.

RNGNet의 유효 depth 평균은 ROI 마스킹에 맞춘 어댑터 수정이며 원본 전체 영상 평균과
다릅니다. 같은 저장 장면에서 경계 집중 문제가 해소되는 것을 확인했습니다.
GFLA는 유효 depth 평균을 쓰지만 분산에는 무효값의 잔차도 포함합니다. 저장 장면 두 개에서
유효값 분산으로 바꾸는 실험은 개선 근거가 없어 **학습 때 사용한 원본 처리를 유지**했습니다.

FoundGrasp 어댑터는 refiner가 100mm 개방 폭으로 평가·선택하고도 원래의 100mm 초과 폭을
남기던 writeback 누락을 복원합니다. 실제 선택 경로의 양수 점수 후보에만 적용하며,
기각된 후보를 살리거나 미평가 폭을 임의로 줄이지 않습니다. 이 교정도 원본과의 차이입니다.

공유 충돌 검사는 **검출기 출력의 width/height/depth**와 원본 검사기의 손가락 형상
(길이 60mm, 두께 10mm)을 사용합니다. 실행 개방 여유, 추가 삽입, 실측 팁 길이 80mm,
잡은 물체와 전체 로봇 경로를 모두 반영한 물리 충돌 검사라는 뜻은 아닙니다.
각 방법의 고유 depth를 일괄 덮어쓰면 파지 원점과 접촉면의 관계가 달라지므로 유지합니다.

## 측정과 재현

- 초기화·워밍업은 추론/택타임 측정에서 제외합니다. `detect_ms`는 워커 통신을 포함하고,
  `inference_ms`는 워커 내부 처리, `post_ms`는 공통 후처리입니다. 순수 신경망 시간과 구분합니다.
- 같은 저장 프레임으로 인식을 비교하려면 모든 방법에 같은 `--npz`를 사용합니다.
  GFLA용 프레임에는 `T_base_cam`이 있어야 합니다. 없는 값은 자동으로 가정하지 않습니다.
- 실장비 성능 비교는 같은 물체 구성·초기 배치를 반복하고 실행 순서를 바꿔 측정합니다.
  자동 연속 실행에서는 파지마다 장면이 달라집니다.
- 이송 완료 횟수는 실제 파지 성공 횟수가 아닙니다. 성공률은 별도 관찰/라벨로 집계합니다.
- 실행별 `manifest.json`과 입력·필터 전후 후보·시간을 보관합니다. 모델 고유 설정과
  비교군별 환경/체크포인트 차이를 함께 기록합니다.

명령과 설치는 [README](../README.md), [상세 가이드](guide.md)를 참고합니다.
